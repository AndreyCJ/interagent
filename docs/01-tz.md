# ТЗ: Программа для отображения подсказок

---

## 1. Зачем

Современные собеседования могут требовать совершенно разные знания, в большей мере это какие то энциклопедические вопросы, которые можно загуглить/посмотреть в документации за 1 минуту.
Но они не проверяют как человек мыслит.

Мне очень понравилось как сказал Тимур Шемсудинов:

```
Человека в наше время нужно оценивать по общей сообразительности, ответственности и честности, а знания - вторично
```

По моему личному опыту могу сказать, что забываются самые, казалось бы, самые простые вещи, которые ты может исользовал или даже делал, но просто забыл.
И плохой интервьювер из-за этого обязательно забракует вас.

Суть приложения - прозрачное окно с подсказками и ответами на вопросы, которые задает собеседующий, либо решение задач по скриншоту экрана.
Функционал может расширяться, это только самые основные функции.

## 2. Основные сущности

| Сущность    | Что хранит                                                                                                       |
| ----------- | ---------------------------------------------------------------------------------------------------------------- |
| Session     | id, chatHistory (Message[]), startedAt                                                                           |
| Message     | role ('interviewer' \| 'user' \| 'assistant'), text, timestamp                                                   |
| AgentConfig | id, name, provider ('local' \| 'openai-compatible'), model, baseUrl, apiKey (зашифр.), systemPrompt, temperature |
| AppSettings | theme ('dark' \| 'light' \| 'transparent'), language, shortcuts, autoStartListening                              |
| Shortcut    | id ('mic_toggle'), label, keys (string[]), enabled                                                               |
| AudioDevice | id, name, isDefault                                                                                              |

## 2.1 Роли

Роли нужны чтобы разделять интервьювера, пользователя и ассистента (ллм агент).

- interviewer - это всегда внешний инпут, такой как системный звук преобразованный в текст через STT, скриншоты - OCR;
- user - это пользователь программы, его инпутом является лишь системный микрофон преобразованный в текст через STT;
- assistant - это ИИ агент, любая модель

## 3. Сценарии.

### Сценарий 1. Автоответ по транскрипции интервьювера

1. Программа обрабатывает звук через whisper (или подобную ллм для перевода голоса в текст) и отправляет его в ллм.
2. Ответ выводится в окне.

### Сценарий 2. Ответ по скриншоту

1. По шорткату или по нажатию на конпку скриншота (можно выбрать область либо весь экран), программа сканирует текст.
2. Ответ выводится в окне.

## 4. Словарь

Минимальный словарь (расширяемый):

### 4.1 Термины

| Термин             | Описание                                                                                                                                                                                                                  |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| STT                | Speech-to-Text — преобразование голоса в текст (Whisper и аналоги)                                                                                                                                                        |
| LLM                | Large Language Model — генерация ответа на переданный контекст                                                                                                                                                            |
| Overlay / HUD      | Прозрачное окно поверх всех окон для отображения подсказок                                                                                                                                                                |
| OCR                | Optical Character Recognition — распознавание текста со скриншота                                                                                                                                                         |
| Screenshot area    | Выделение области экрана для захвата (регион или весь экран)                                                                                                                                                              |
| Agent / Агент      | Конфигурация LLM: provider (local / openai-compatible), model, baseUrl, apiKey (зашифрован), systemPrompt, temperature. Инференс по выбору: llama.go локально или облачный OpenAI-compatible (ADR-001, ADR-004, ADR-005). |
| Session / Сессия   | Локальный чат с историей вопросов и ответов текущего интервью                                                                                                                                                             |
| Shortcut / Шорткат | Глобальная комбинация клавиш для триггера действий (скриншот, mute)                                                                                                                                                       |

### 4.2 События приложения

Рантайм-события (runtime events) — единственный источник: `04-events.md`.
В этом документе события не дублируются, чтобы избежать рассогласованности.

## 5. Роли пользователей

Система однопользовательская. Единственная роль — **Кандидат**: пользователь, проходящий интервью. Он управляет сессией, настраивает агентов и шорткаты, просматривает подсказки. «Оператор» — это тот же кандидат в режиме калибровки перед собеседованием.

## 6. Интеграции

| Система         | Назначение                     | Варианты                                                              | Примечание                                                         |
| --------------- | ------------------------------ | --------------------------------------------------------------------- | ------------------------------------------------------------------ |
| STT (Whisper)   | Перевод голоса в текст         | whisper.cpp (локально)                                                | ADR-001: только локальный инференс; облачный STT не поддерживается |
| LLM             | Генерация ответа               | llama.go (локально, pure Go) + облачные OpenAI-compatible (по выбору) | ADR-001, ADR-004, ADR-005. Локальные модели 3–8B                   |
| OCR             | Распознавание текста на скрине | Apple Vision (macOS)                                                  | ADR-002: только Apple Vision для v1                                |
| Скриншот экрана | Захват изображения             | Нативное API ОС (CGDisplay, Win32)                                    | macOS: `CGDisplayCreateImage` / ScreenCaptureKit, Windows: DXGI    |

Все интеграции — внешние, подключаются через адаптеры. Ядро не должно зависеть от конкретного провайдера.

## 7. Ограничения и допущения

Нефункциональные требования — см. [02-nfr.md](02-nfr.md).

- **Платформа.** Первая версия — macOS (ARM/Intel). Windows — следующий этап.
- **Фреймворк.** Wails v2 — единственный бэкенд. Замена фреймворка не планируется.
- **Always-on-top.** Окно всегда поверх всех окон. По умолчанию — click-through (сквозной клик), кликабельный режим переключается глобальным шорткатом (ADR-006).
- **Одно окно.** Приложение работает в одном окне. Мультимониторные конфигурации — позже (out of scope для v1).
- **Микрофон.** Предполагается наличие рабочего микрофона. Без него аудио-сценарий недоступен.
- **Интернет.** Для STT не требуется (whisper.cpp локально). Для облачного LLM нужен интернет и явное включение облачного провайдера пользователем (см. ADR-004).
- **Аккаунт.** Серверный бэкенд не предусмотрен. Всё хранится локально (SQLite, см. ADR-003). apiKey хранится зашифрованным (ADR-004).

## 8. Этапы разработки

Каждый этап — вертикальный слайс: сначала пишутся тесты (spec / контракты), ревью и аппрув тестов, только потом реализация. Этап считается готовым, когда тесты зелёные.

### Этап 1: TDD + каркас проекта

- Настройка инструментов: Go (`go test` + testify / gotest), фронтенд (vitest + vue-test-utils), e2e (playwright)
- CI-пайплайн: тесты на каждый коммит (GitHub Actions)
- Пустые тесты для всех будущих модулей (интеграции) — контракты и ожидаемое поведение
- Ты ревьювишь тесты → аппрувишь → идём дальше

### Этап 2: Ядро оверлея + ручной ввод

- Написать тесты на поведение оверлея (открыть/скрыть, click-through, шорткаты) → ревью
- Прозрачное click-through окно (Wails + нативные вызовы) с переключением в кликабельный режим по глобальному шорткату (ADR-006)
- Поле ввода текста вручную → отправка в LLM → вывод ответа (в кликабельном режиме)
- Сохранение истории сессии
- Глобальный шорткат для показа/скрытия окна и для переключения режима

### Этап 3: Интеграция ЛЛМ агентов (adr-001, adr-004), транскрипция аудио (STT → LLM)

- Написать тесты на контракт STT-адаптера (захват аудио, отправка, ответ) → ревью
- Написать тесты на интеграцию ллм агентов (adr-004)
- Захват аудио с микрофона и системного звука (нативное API)
- Интеграция STT (Whisper — локально, whisper.cpp)
- Интеграция ллм агента
- Автоматическая отправка транскрибированного текста в LLM
- Визуальный индикатор "слушаю" / "печатаю"

### Этап 4: Скриншоты (Screenshot → OCR/Image → LLM)

- Написать тесты на захват экрана, OCR-адаптер, multimodal → ревью
- Захват скриншота (регион / весь экран) по шорткату
- OCR распознавание текста → отправка текста в LLM
- Отправка скриншота как есть в LLM (multimodal, ADR-005) — картинка напрямую, либо текст через OCR (выбор пользователя; при облачном агенте и direct-image — скриншот уходит в облако, NFR-02/ADR-004)

### Этап 5: Настройки, агенты, полировка

- Написать тесты на UI настроек, сохранение конфига, автообновление → ревью
  - UI для управления агентами (provider, model, baseUrl, apiKey, systemPrompt, temperature)
- UI для шорткатов и тем оформления
- Автообновление (через встроенный механизм Wails / Homebrew)
- Телеметрия (опционально, opt-in)
