# ADR-001: Локальный инференс LLM/STT vs Облачные API

**Дата:** 2026-07-29
**Статус:** ✅ Принято
**Изменено:** 2026-08-01 (решение по LLM дополнено гибридным режимом)
**Связанные документы:** 01-tz.md §6–§7, 02-nfr.md (NFR-02, NFR-11), 05-architecture.md §3

---

## Контекст

Приложению требуется два ключевых внешних сервиса:

- **STT** (Speech-to-Text) — перевод голоса интервьювера в текст
- **LLM** (Large Language Model) — генерация ответа по транскрипции или скриншоту

Оба сервиса можно запустить локально (whisper.cpp, llama.cpp) или использовать облачные API (OpenAI, Anthropic). У каждого подхода есть tradeoffs, влияющие на архитектуру, UX и распространение приложения.

## Варианты

### A. Полностью локальный инференс

| Компонент | Технология                                               |
| --------- | -------------------------------------------------------- |
| STT       | whisper.cpp (C++ биндинги через cgo или внешний процесс) |
| LLM       | llama.cpp / llama.go / Ollama (REST на localhost)        |

**Плюсы:**

- Полная конфиденциальность — данные не покидают устройство
- Работает офлайн
- Нет затрат на API (одноразовая стоимость железа)
- Не нужен аккаунт / API-ключ

**Минусы:**

- Значительное потребление RAM/VRAM (минимум 4–8 ГБ для вменяемой модели)
- Заметная нагрузка на CPU/GPU (может мешать работе в IDE)
- Скорость ответа ниже, чем у API (особенно на Apple Silicon без Metal)
- Бинарник приложения разрастается (нужны биндинги C/C++)
- Сложная кросс-компиляция и сборка
- Пользователь должен скачивать файлы моделей (гигабайты)

### B. Облачные API

| Компонент | Технология                                                |
| --------- | --------------------------------------------------------- |
| STT       | OpenAI Whisper API / Deepgram                             |
| LLM       | OpenAI Chat Completion / Anthropic Claude / Google Gemini |

**Плюсы:**

- Минимальная нагрузка на устройство
- Высокая скорость и качество ответов (лучшие модели)
- Простая интеграция — HTTP-запрос с ключом
- Маленький бинарник, простая сборка
- Модели всегда актуальны, не нужно обновлять вручную

**Минусы:**

- Требуется интернет
- Данные уходят на сервер провайдера (конфиденциальность под вопросом)
- Стоимость за токены (PAYG)
- Нужен аккаунт и API-ключ с платёжным методом
- Vendor lock-in (привязка к одному провайдеру)

### C. Локальный STT + гибридный LLM (выбор пользователя) [выбран]

Настройка: `AgentConfig.provider = 'local' | 'openai-compatible'`. STT всегда локальный (whisper.cpp).

**Плюсы:**

- Пользователь сам выбирает баланс приватности/скорости для LLM.
- STT остаётся полностью локальным — аудио никогда не уходит в сеть.
- Можно начать с локального LLM, переключиться на облачный при необходимости.

**Минусы:**

- Нужно поддерживать два бэкенда LLM (локальный + HTTP-клиент).
- Усложняется код: абстракции, адаптеры, обработка ошибок обоих путей.
- При облачном LLM данные текста покидают устройство (с согласия пользователя и с индикатором).

## Критерии выбора

| Критерий                   | A (локально)   | B (облако для всех) | C (локальный STT + гибридный LLM) |
| -------------------------- | -------------- | ------------------- | --------------------------------- |
| Приватность аудио/скринов  | ✅             | ❌                  | ✅ (STT локальный, LLM — выбор)   |
| Офлайн-режим               | ✅             | ❌                  | ⚠️ (локальный LLM офлайн)         |
| Скорость ответа            | ⚠️ (3-10 сек)  | ✅ (1-3 сек)        | ⚠️/✅ (зависит от провайдера LLM) |
| Нагрузка на устройство     | ❌ (высокая)   | ✅ (низкая)         | ⚠️ (зависит)                      |
| Сложность разработки       | ❌ (высокая)   | ✅ (низкая)         | ⚠️ (средняя)                      |
| Стоимость для пользователя | ✅ (бесплатно) | ❌ (PAYG)           | ⚠️ (опционально)                  |
| Размер бинарника           | ❌ (200+ МБ)   | ✅ (маленький)      | ❌ (локальные модели)             |

## Решение

- **STT — строго локально.** `whisper.cpp` (C++ биндинги или внешний процесс). Облачный STT не поддерживается. _Конкретная интеграция выбрана в ADR-005 (официальный Go-биндинг, cgo)._
- **LLM — гибрид (по выбору пользователя).**
  - **Локальный:** `llama.cpp / llama.go` (инференс на CPU/Metal). _Выбран `llama.go` (pure Go) — см. ADR-005._
  - **Облачный:** OpenAI-совместимые провайдеры по выбору пользователя (OpenAI, Groq, LM Studio, Ollama и др. через `baseUrl` + `apiKey`). См. ADR-004.

### Обоснование

1. **Приватность — критична для аудио/скринов.** Сценарий собеседования требует, чтобы данные микрофона и скриншоты гарантированно не покидали устройство. Поэтому **STT всегда локальный** (whisper.cpp): аудио в сеть никогда не уходит.
2. **LLM — пользователь решает.** Текст (транскрипция или OCR) может отправляться в облачный LLM **только если пользователь явно включил облачного провайдера для агента** (см. ADR-004). Это сопровождается индикатором в оверлее.
3. **Офлайн-режим.** Собеседования проходят в том числе в офисах с корпоративными VPN. Локальный LLM работает без сети.
4. **Стоимость.** Локальный инференс — бесплатно после единоразовой покупки железа. Облачный — PAYG, легко набегает. Пользователь выбирает, когда платить.
5. **Apple Silicon.** M-серия даёт достаточную производительность для whisper.cpp + малых LLM (3–8B) через Metal.

### Компромиссы

- Увеличенный порог входа: локальная модель нужно скачать (несколько ГБ).
- Локальный LLM уступает GPT-4/Claude 3.5 по качеству — приемлемо для подсказок, но заметно для сложных задач.
- На старых Intel Mac время ответа локального LLM может превышать 5 сек — выводить предупреждение и рекомендовать M-серию (или переключить на облачного провайдера).
- При использовании облачного LLM данные текста покидают устройство (в соответствии с явным выбором пользователя и с индикатором). Данные микрофона и скриншотов никогда не покидают устройство.
