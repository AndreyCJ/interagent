# ADR-002: OCR — Apple Vision vs Tesseract

**Date:** 2026-08-01
**Status:** Accepted
**Related documents:** 01-tz.md §6, 05-architecture.md §3

---

## Context

The app must extract text from a screen screenshot. The primary target platform is macOS. Requirements: high accuracy (typical UI text), minimal latency to meet NFR-01 (target 2 s, max 5 s for the whole Screenshot → OCR → LLM → Render pipeline).

## Options

### A. Apple Vision (Vision Framework)

| Component | Technology                                                |
| --------- | --------------------------------------------------------- |
| OCR       | `VNRecognizeTextRequest` (Apple Vision), native macOS API |

**Pros:**

- Native, fast (Metal / hardware acceleration), often 2–5× faster than Tesseract.
- Good quality on typical UI text (fonts, contrast).
- No external dependencies, small binary.
- Works offline, no language package downloads.

**Cons:**

- macOS 10.15+ only (platform-limited — fine for v1).
- Languages limited to what Vision supports (usually EN + system languages).
- No cross-platform replacement without an adapter.

### B. Tesseract 5

| Component | Technology                                           |
| --------- | ---------------------------------------------------- |
| OCR       | `tesseract` via a cgo wrapper (go-tesseract / forks) |

**Pros:**

- Cross-platform (Linux, Windows, macOS).
- Wide language support (traineddata).
- Hardware-independent.

**Cons:**

- Slower than Apple Vision (especially without optimizations).
- Requires cgo → complicates cross-compilation (`go build` on CI).
- Language packages must be shipped (`rus.traineddata`, etc.) — size grows.
- Worse accuracy on small/blurry UI text.

## Selection criteria

| Criterion      | A (Vision)      | B (Tesseract)  |
| -------------- | --------------- | -------------- |
| Accuracy on UI | ✅ (better)     | ⚠️             |
| Speed          | ✅ (faster)     | ⚠️             |
| Cross-platform | ❌ (macOS only) | ✅             |
| cgo / build    | ✅ (native)     | ❌ (cgo)       |
| Size           | ✅ (small)      | ⚠️ (languages) |
| Offline        | ✅              | ✅             |

## Decision

Option **A — Apple Vision** chosen for v1 (macOS-only).

### Trade-offs

- A cross-platform OCR adapter will require Tesseract or an equivalent when porting to Windows/Linux — that is a separate ADR.
- The UI language is unrelated to the OCR language: Vision recognizes text on screen regardless of `AppSettings.language`.
